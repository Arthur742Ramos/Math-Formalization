# Verification evidence boundaries

Each receipt must identify its exact source, configuration and metadata
digests, toolchain and dependency pins. Source archives and copyable fields
are checked against that frozen commit. Receipts live outside the submitted
package to avoid changing the source after verification merely to report a
result.

The source has six selected theorem targets and no definition targets. The
Challenge compiles under a fresh module alias without candidate build paths.
The native regression uses unchanged pinned `Lake.Check.compareAt` and
`Lake.Check.checkAxioms`, all 26 primitive targets, and a negative control
altering the fixed limit definition's body in memory. Actual outcomes are
recorded in the source-bound receipt; this description alone is not a pass.

Native Lean, NanoDa and con-ron kernel results do not substitute for Palomar's
full reusable workflow or its protected rendering job. A generic service pass
does not establish con-ron acceptance when a report records a declined replay.
Public registration and private editorial status require separate evidence.

No registry action, merge, security-setting change or grant of repository
access is performed by running this package's ordinary Lean checks.
