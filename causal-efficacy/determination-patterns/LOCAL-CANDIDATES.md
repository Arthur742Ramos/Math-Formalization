# Local Comparator candidates

These are development candidates, not registry submissions. The authoritative
release remains subject to exact-commit canonical verification, rendering,
independent review and intake.

`comparator-pattern-central.json` selects the complete
`DeterminationPatterns.exact_pattern_from_components` equivalence. The
Challenge has one visible definition set and a hole-free proof, organized into
carrier and context, paths, witness, sufficiency, necessity and conclusion.
It imports only `Init`. The Solution imports the package composition theorem.
The selected statement preserves the arbitrary carrier and parent sets,
partition and legal context, quantification over a single normalized monotone
edge-relevant mechanism, and both extrema. The explicit status mechanism is a
proof witness, not a separate selected claim in this configuration.

The central Challenge is 774 lines. It exceeds the preferred 300-line review
threshold. A preceding full-pattern Challenge had an HTML output over the
renderer limit; this reorganized candidate has not yet been rendered. Its
readability and output size need assessment on the exact release source. Do not
infer renderer compliance from its source line or byte count.

`comparator-representation-bridge.json` selects the Boolean/Prop gate equation,
the four gate truth-table statements and the natural successor identity. Its
small Challenge contains the same two gate definitions as the Solution's
package and imports only `Init`; its Solution imports `RepresentationBridge`.
Definitions are not listed as definition targets: the Comparator's theorem
dependency comparison must compare their ordinary values rather than treating
them as definition holes. This Lean-side comparison does not import Isabelle
proofs or establish cross-kernel identity.

Local paranoid Comparator checks for both configurations passed on the
uncommitted candidate source. In an isolated control, the selected Boolean
equation still compiled after both gate definitions were changed to constant
false; Comparator rejected the changed Boolean definition. Separate controls
in the six-theorem configuration wrapped each definition in `id` and were
rejected at the corresponding definition. Those two wrappers preserve meaning
and test syntactic comparison; the coordinated mutation is a semantic control
for one theorem, not comprehensive material-definition coverage. These local
checks do not replace the canonical pipeline or per-configuration semantic
review.
