This document does not grant execution, security, merge or intake authority.
Applicable explicit project authorization and reviewed execution plans control
those actions. This protocol does not assert the current status of any run.

## Before execution

1. Freeze the exact source and metadata/config/toolchain/dependency digests.
2. Authenticate the pinned pipeline and review inert caller bytes outside
   active workflow directories, including resource limits and storage retention.
3. Establish applicable authorization for that bounded attempt and conditional
   runner setup. Reuse settled budget/workflow facts for the same arrangement;
   materially different arrangements need their own evidence and authority.
4. Check existing and uncertain runs before activation; never duplicate one.

## Verification and conditional rendering

Use the exact reviewed standard disposable runner and confinement profile.
No paid/larger/Namespace runner, global security disable, credential or account
setting change is implied. Pinned conditional AppArmor/cgroup setup requires
its applicable action-time authorization. Stop if confinement/capacity fails.

Full verification must independently compile the canonical frozen Challenge,
check dependency provenance and protected controls, compare exact selected
exports, and record mandatory Lean/NanoDa and actual advisory con-ron results.
Never call a declined kernel accepted. Preserve original report/artifact hashes,
run/attempt/source/pipeline identity and independent receipt review.

Under an applicable bundled approval, activate one conditional render only
after successful same-source verification and acceptance of its original
receipt. Retain exact source/Challenge/config/Verso bindings, bounded sanitized
output and original rendering report. Do not infer visual inspection from
successful rendering. No computation retry is implicit in this protocol.

## Release handoff

Review mathematical fidelity, imported definitions, attribution and scope
separately from kernel acceptance. Verify actual publication/registration
prerequisites and existing/pending intake status before a registry action.
Honor the explicitly assigned authors/maintainers and honest AI disclosures.

Review the exact proposed commit's own documentation and metadata against
completed results. Preserve stage history outside frozen source and do not
attribute another commit's report to an edited source. Use the complete tracked
project file archive required by the release guard, including historical
project evidence. Run the full exact-source guard, retain its result and
independently review it. Follow required repository protections for any merge.
Mechanical acceptance does not establish novelty, editorial approval or public
registration; those decisions have separate evidence.
