# Dependency and scope map

Current status: both explicit syntax translations have correctness proofs for the public finite three-symbol unary model. The following entries record successive development checkpoints; statements of missing work in those entries describe their local stage, not necessarily current package status. Independent review, fresh validation, and distribution and computational-dependency audits remain pending.

Audit basis: Mathlib `065356127b1dc0016f66b7283ce0ce2c4055aa55` and Lean `v4.35.0-rc2`, with the nine-package dependency graph pinned in the lockfile. Searches of `Mathlib/Computability` and `Mathlib/Logic` for lambda calculus and Church numerals returned no matches; this is a bounded search, not a claim that no equivalent development exists elsewhere. Historical validation is described in `VALIDATION.md`.

* `Mathlib/Computability/PartrecCode.lean` supplies `Nat.Partrec.Code`, its partial evaluator, and `Nat.Partrec.Code.exists_code` relating arbitrary unary partial recursive functions to codes. Its codes use pairing, composition, primitive recursion and minimization; a compiler to full-beta Church terms remains to be constructed and verified, with strictness established where needed.
* `Mathlib/Computability/TuringMachine/Config.lean` supplies a list-valued code language and sequential evaluation; its `exists_code` connects a fixed-arity `Nat.Partrec'` function to this language. `TuringMachine/ToPartrec.lean` provides `Turing.PartrecToTM2.tr`, `tr_eval` and `tr_supports`: it compiles that list-code model to a finitely supported TM2 stack machine and proves evaluation correspondence. Aligning unary `Nat.Partrec.Code` with the fixed-arity/list-code semantics and numerical encodings is still work.
* `TuringMachine/StackTuringMachine.lean` and `PostTuringMachine.lean` contain TM2-to-TM1 and TM1-to-TM0 translations and simulation theorems. Their exact input, output, finite-support and halt hypotheses must be traced before selecting the public machine interface. The stack-machine simulation's output theorem has hypotheses and cannot be replaced by an unqualified equation. A machine-to-partial-recursive translator for arbitrary permitted machines, with malformed outputs treated as absence of a numerical result, has not been identified or proved here. It remains a central obligation, not an assumed equivalence.
* For lambda-to-machine, the syntax encoding, effective one-step enumeration, exhaustive search, confluence and numerical-result uniqueness now establish partial recursiveness of every lambda observation. A constructive code extractor and verified construction from that code to a standard machine must still preserve exact numerical results.
* For machine-to-lambda, numerical observations of each concrete three-symbol finite table machine are partial recursive. Constructively extract or build a corresponding code, compile it into a closed Church term, and prove defined/undefined correspondence, including malformed halts. An existential representability theorem alone does not provide the explicit translator; general finite-alphabet simulation is also open.

The target is an equivalence of result relations, not a divergence equivalence. The final model choice is provisional until the two machine directions and malformed-output bridge are checked. Canonical term coding and primitive recursiveness of its encoder, decoder, constructors and image predicate are proved; the general finite-alphabet machine-to-recursive direction, explicit compilers and both translation correctness results are pending. No new axioms or proof placeholders are permitted.

## Concrete finite-machine interface

`LambdaTuring.Machine.Program` is a finite list of transition-table entries, addressed by finite state and a three-symbol alphabet. Missing entries halt; extra entries are unreachable. Its two-sided finite lists use implicit blank tails. Input `n` is `n+1` ones; output is read from the current cell rightward and accepted only as a positive run of ones followed exclusively by blanks. A marker, a one after a blank, or an empty output is nonnumerical. `Yields` requires a reachable halting configuration and successful decoding; terminal-run determinism gives `yields_unique`; `decode_append_blanks` proves invariance under finite blank extensions. `mark_no_numerical_result` proves that a machine can reach a halt with no numerical result. `LambdaTuring.MathlibBridge` maps both concrete tape sides to Mathlib's blank-quotient tape and proves left and right moves, step commutation, initial/input correspondence, well-defined quotient decoding, complete evaluation correspondence, and numerical-result and no-numerical-result equivalences. It also constructs an explicit table for every Mathlib TM0 with state type `Fin (states + 1)` over the three selected symbols, and proves recovery of its transition function and numerical outcomes. The decoder reads the current cell and the right tape; it deliberately ignores the left tape. A simulation from other finite alphabets and state types to this interface and a connection to the Isabelle machine model remain to be proved. The compiler target remains provisional until the Mathlib TM2 → TM1 → TM0 simulations and their finite-support, input and output-membership hypotheses have been discharged. Mathlib's existential code-representation theorems are not executable code extractors.


## Confluence provenance and lambda observations

The files `LambdaTuring/Upstream/DeBruijn.lean`, `Beta.lean` and `Parallel.lean` are adapted from the corresponding files of Zayn Wang and Maksym Radziwill in the Apache-2.0-licensed, open [CSLib PR 475](https://github.com/leanprover/cslib/pull/475), immutable head `cd9bd6ba0537764eb422532400e99b2c90f34256`. Original copyright notices are retained. The port removes an unused notation instance and replaces relation-notation macros; `Upstream/Confluence.lean` adapts the final argument to the pinned Mathlib `Relation.church_rosser` lemma. The upstream head targets Lean 4.36.0-rc1, whereas these adapted modules were checked under Lean 4.35.0-rc2.

`SemanticBridge` proves inverse term translations, shift and substitution preservation, and beta-step preservation in both directions, then transfers confluence. `NumericalSemantics` defines exact `Part Nat` observation semantics. `Explore` proves that bounded exploration enumerates exactly bounded full-beta paths, and `ObservationSearch` proves Church numeral decoding and exhaustiveness. `UnboundedSearch` proves the unbounded search equals the partial observation, and proves partial recursiveness conditional on computability of the bounded search. The later substitution and beta-step modules discharge the computability premise; no explicit code translator is supplied. The imported source, adaptations, semantic mapping and exact checkpoint require independent review and structured provenance before any submission.


`TermCode` injects terms into Mathlib `Nat.Partrec.Code` and proves `decodeTerm c = some t` exactly when `c = encodeTerm t`. `FoldCode` shows the canonical-code image is primitive recursive and constructs a `Primcodable Term` instance through the effective subtype; the encoding, decoding of variable constants, and variable, abstraction and application constructors are primitive recursive. `DecodeComputable` proves that decoding arbitrary code trees is primitive recursive. `TermCode` also proves primitive recursiveness of the Church numeral code sequence. This establishes the syntax infrastructure used by the later substitution and beta-step proofs.


The term destructors and Church-numeral constructor and recognizer are primitive recursive. `SearchComputable` constructs breadth-first expansion, proves exact reachability, and derives `Nat.Partrec (numericalValue t)` from an explicit `Primrec betaSteps` premise. The later modules now discharge that premise; this alone does not construct a Turing machine.


## Effective full-beta observation

`TermSize` and `LiftTable` use size-bounded tables over structural code folds to establish primitive recursiveness of depth-sensitive lifting and iterated lifting. `SubstTable` applies the same technique to prove primitive recursiveness of capture-avoiding substitution at arbitrary depth. `BetaStepComputable` folds over term codes to compute every single full-beta reduct, and `LambdaTuring.numericalValue_partrec` combines this with exhaustive search and numeral uniqueness to show that every term has a partial recursive numerical observation. The correctness theorem retains the exact no-numerical-result semantics. These facts are extensional: Mathlib representability by codes is existential, so they do not by themselves provide an executable code extractor or either required Turing-machine translation. These modules require independent review.

`MachineRun` characterizes numerical observations by bounded execution of the finite table machine. `MachineSearch` searches those bounds and proves its partial result has exactly the machine's numerical outcomes, including undefinedness for malformed halts. The later machine coding and exact-step proofs establish partial recursiveness by a separate exact-step search; computability of the bounded-observation function itself and an explicit code translator remain open.

`MachineCoding` gives primitive-recursive encodings of the finite symbols, actions, tapes and configurations, and proves primitive recursiveness of transition, input and numerical decoding. `MachineExact` proves that exact-step iteration and numerical halting observation are primitive recursive, then derives `Machine.machineValue_partrec` for every finite transition table over the selected three-symbol alphabet. The theorem captures both nonhalting and malformed halting as absence of a numerical result. It is extensional and provides no explicit code extractor; arbitrary finite-alphabet simulation, both translators and their correctness are still open. These new modules require independent review.

`ConstantCompiler` gives an executable, primitive-recursive compiler from Mathlib `Nat.Partrec.Code` to closed lambda terms for its canonical constant codes and identity code. Its soundness theorem equates the exact partial numerical observations with Mathlib code evaluation on every input. The compiler returns `none` outside this syntactic fragment; that result denotes an unsupported code, not semantic divergence. Pairing, projection, general primitive recursion and strict minimization remain to be compiled; composition of the supported base fragment is addressed below. The fragment needs independent review.

`CPS` formalizes a strict continuation invariant: defined computations pass their result to any continuation; undefined computations have no beta-reachable normal form for any continuation. It proves that wrapping such a program with the identity continuation exactly represents its partial numerical function, and provides a primitive-recursive CPS compiler for canonical constant and identity codes. The invariant and normalization argument follow the related Isabelle `Lambda_CPS` theory and the continuation method credited there to Norrish (2011). General recursion and minimization, as well as a total compiler, remain open; these new results require independent review.

`CPSComposition` proves that strict CPS composition represents the partial-function bind, including when either stage is undefined. It constructs a primitive-recursive compiler total on the syntactic fragment generated by canonical constant codes, identity, and arbitrary finite composition, and proves the resulting closed term has exactly the source code's numerical observations. A `none` compiler result means unsupported syntax. Pairing, projections, primitive recursion, minimization, and the complete translator remain open; this increment requires independent review.

`MachineCompilerBase` constructs concrete finite transition tables for Mathlib's zero and identity codes. The zero machine scans to the first blank, writes one, and halts; the decoder ignores the left tape. Proofs show exact numerical and no-numerical-result correspondence with the source code through the Mathlib TM0 bridge. Unsupported codes return `none`, meaning outside this two-code fragment. This is not a general machine compiler and requires independent review.

`ChurchSuccessor` proves the standard successor term reduces every Church numeral to its successor and establishes its strict CPS representation. `CPSWithSuccessor` gives a primitive-recursive compiler that is total on codes generated from canonical constants, identity, successor and finite composition; its emitted closed terms exactly represent Mathlib code evaluation. Unsupported syntax returns `none`, which is not semantic divergence. Pairing, projections, recursion and minimization remain open, as do a general machine compiler and independent review.

`MachineSuccessor` extends the finite-table compiler to Mathlib's successor code, alongside zero and identity. Its machine appends one unary symbol and returns to the left edge before halting. Correctness proves exact numerical and no-numerical-result correspondence through Mathlib TM0. Other source codes remain unsupported; this does not implement general machine compilation or arbitrary finite-alphabet simulation. Independent review is pending.

`FragmentBridge` combines the two current compilers and proves that every successful compilation has exactly matching lambda and Mathlib TM0 numerical observations, including absence of numerical output. It proves the common compiler currently accepts exactly Mathlib's zero, identity, and successor codes. All three are total, so the no-output equivalence has no undefined input in this fragment. The lambda compiler alone accepts a larger composition fragment. This is a limited common-code result, not the full lambda–Turing equivalence or a translator for arbitrary terms or machines; independent review is pending.

`CPSBottom`, `MachineBottom`, and `BottomFragmentBridge` extend the shared fragment with the specific undefined code `rfind' (const 1)`. Its evaluation is proved undefined on every input; the CPS program supplied any Church input and continuation has no beta-reachable normal form and the compiled finite machine loops. The extended common compiler accepts exactly zero, identity, successor, and this one undefined code, and proves exact numerical and no-numerical-result correspondence. A constant composed after the undefined CPS program is also proved undefined, demonstrating strictness non-vacuously. This example does not identify all nonnumerical results with divergence or implement general minimization. Independent review remains pending.

`CPSWithBottom` extends the primitive-recursive lambda compiler to finite compositions of canonical constants, identity, successor, and the specific undefined code. It is proved total on that inductively specified fragment and exact for the source evaluation, including undefinedness. A checked instance compiles a constant after the undefined code and proves the result has no numerical observation. This is not general minimization or the full recursive-code compiler.

`ChurchPairs` establishes closed Church-term pairing and projections, numeral iteration, indexed iteration, addition, multiplication and zero testing. These operations support the separate numeric `Nat.pair` construction; `Nat.unpair` remains open. Mathlib uses a square-based pairing formula, whereas the related Isabelle project uses a Cantor-style numeric pairing; the two encodings require an explicit bridge.

`ChurchPredecessor` proves Church predecessor, truncated subtraction, strict comparison, and a closed binary Church program computing Mathlib's actual square-based `Nat.pair` on all natural inputs. The binary representation theorem also proves uniqueness of numerical results under full beta reduction. The strict recursive-code `pair` compiler is described below; `Nat.unpair` and the general equivalence remain open; independent review remains pending.

`CPSPair` proves strict two-input CPS pairing against Mathlib's actual `Code.pair` evaluator, including undefinedness of either subcomputation. `CPSWithPair` gives a primitive-recursive lambda compiler proved total and exact on the fragment generated by constants, identity, successor, the specific undefined code, finite composition, and numeric pairing. A compiled pairing example with an undefined input is proved to have no numerical result. Numeric unpairing/projections, general recursion and minimization, general machine compilation, and independent review remain open.

`DirectCertificateValidation` and `DirectCertificateValidatorCode` validate arbitrary numeric encodings of finite path certificates. `DirectSafeCertificate` rejects invalid certificates, and `DirectCertificateObservation` proves that a numeral is observable by some certificate exactly when it is reachable by full beta reduction. `DirectLambdaEvaluator` builds an explicit recursive evaluator for the exact partial numerical semantics, and `DirectLambdaToMachine` combines it with the finite unary-machine compiler. `explicitTranslations_correct` states both translation directions for arbitrary source syntax and every public finite three-symbol table; absence of any numerical result follows pointwise. The direct evaluator program has no axiom dependencies. Lean reports standard axioms including `Classical.choice` on the machine translation definition, so its computational dependency closure still needs review. A code-generation probe compiles an unselected translation branch but does not materialize its large table or provide a practical size bound.
