# Constructive compiler obligations

Current status: both explicit syntax translations have correctness proofs for the public finite three-symbol unary model. The following entries record successive development checkpoints; statements of missing work in those entries describe their local stage, not necessarily current package status. Independent review, fresh validation, and distribution and computational-dependency audits remain pending.

The source language is the pinned Mathlib `Nat.Partrec.Code`; its evaluator determines the exact partial numerical semantics. `CPSTotalCompiler` defines a total structural compiler from every source code to a closed lambda term, proves its CPS and unary numerical semantics exactly match `Code.eval`, and proves that the compiler is primitive recursive. This is a code-to-lambda compiler, not yet either requested translation between arbitrary lambda syntax and conventional machine tables.

The compiler handles Mathlib’s square-based `Nat.pair` and its numeric inverse, strict composition, primitive recursion, and offset minimization. `StandardReduction` proves that every finite full-beta reduction has a standard reduction, derives the variable-head prefix and weak-normalization head-accessibility consequences, and discharges the explicit hypotheses in the earlier observable-search construction. In particular, the minimization proof handles both a finite earlier undefined test and an infinite sequence of defined positive tests. No-numerical-result means absence of a reachable Church numeral; it is not identified with divergence.

The earlier common lambda/machine compiler still accepts exactly zero, identity, successor, and the specific undefined code `rfind' (const 1)`. The new lambda compiler does not extend that machine fragment. For machines, Mathlib’s `Turing.PartrecToTM2.tr` compiles a different list-valued code language. An explicit structural bridge is needed; Mathlib’s `exists_code` statements are existential and are not executable extractors. The TM2-to-TM1 output theorem `TM2to1.tr_eval` requires membership of outputs from both evaluations, while its domain theorem supplies only domain equivalence. Finite support, alphabet/state encoding, and unary decoding must reach the public TM0 table interface. No general machine compiler or arbitrary-finite-alphabet simulation is claimed.

The extensional lambda and machine partial-recursiveness results do not themselves give executable code-generation functions from syntax. Those functions and their verified compositions with the code compilers remain necessary for the requested translations. Full independent review, source-diff and distribution-license review, and complete end-to-end validation remain prerequisites for submission.

The extensional consequences now include `LambdaComputable f ↔ Nat.Partrec f` and, for every finite three-symbol table machine (or Mathlib TM0 with the corresponding finite state type), existence of a closed lambda term with exactly the same decoded numerical results. These theorems use the existential `Code.exists_code`; they are not executable syntax translators and do not establish the opposite machine-existence direction.

`ListCodeBridge` starts the explicit numeric-code-to-list-code bridge with zero, successor, identity, the specific bottom code and finite compositions. It proves exact singleton-list semantics, the actual TM2 evaluation equation, and finite support; a loop example proves undefinedness is non-vacuous. The translation remains partial and does not yet provide projections, primitive recursion, minimization, finite TM0 tables or the public unary tape interface; the later pair compiler adds strict pairing.

`TM2TM0Bridge` now composes the two Mathlib machine simulations and proves domain equality and decoded numeric-result equivalence for the restricted fragment. It retains both output-membership assumptions in the TM2-to-TM1 result theorem and proves the decoder respects blank extension. The TM0 program has finite state support, but its support is classically constructed and is not an executable finite-table extraction. Its alphabet and input/output conventions are the simulation encoding, not yet the public three-symbol unary interface.

The strict-pair extension explicitly compiles the two subprogram results into a two-element list and computes the exact Mathlib `Nat.pair` using verified list-code arithmetic. It composes through the encoded TM0 simulation and the total lambda compiler with result and no-result equivalence. This is still a partial source-code compiler: projections, primitive recursion, and minimization need explicit implementations. The simulated-tape decoder is validated for reached outputs and does not reject all malformed tapes.

The numeric-projection extension constructs square root by list-code primitive recursion, then implements both components of Mathlib `Nat.unpair` using its exact square-based definition. The resulting explicit compiler handles zero, successor, left, right, one bottom code, finite composition and pairing. Its list-code semantics and encoded TM0/lambda correspondence are proved. General source-code primitive recursion and strict minimization, effective finite-table extraction, and the conventional unary interface remain open.

The strict primitive-recursion extension uses a proved partial-iteration invariant, rather than the earlier total-arithmetic-only recursion theorem. The compiled step reconstructs Mathlib’s nested numeric-pair argument; undefined base and intermediate computations remain undefined. This adds `prec` to the supported source grammar and preserves the encoded TM0/lambda result equivalence. General offset minimization remains the only unsupported source-code constructor, apart from the one specifically supported bottom instance. Effective finite-table extraction, the public unary interface, arbitrary-syntax translators and full review remain open.

The total list-code compiler now handles all numeric-code constructors, including offset minimization with partial tests. Its search proof requires each earlier test to have a nonzero result, preserving undefinedness as well as nontermination. It composes with the encoded Mathlib TM0 simulation and the lambda compiler, with exact numerical and no-result correspondence. A later module constructs a finite transition table for the encoded simulator. Translation to the conventional three-symbol unary interface and extraction of recursive codes from arbitrary lambda or machine syntax remain open.

Finite-table extraction now uses a direct list enumeration, avoiding `Finset.toList` and its noncomputable choice. It constructs data-only rows with natural-number states, a five-field encoded alphabet symbol and move/write actions, and proves executable lookup agrees with the numbered TM0 transition function. A simulation proof transfers exact evaluation and numerical observations to the table interpreter. This is a finite conventional transition table over the 1,250-symbol encoded alphabet, not yet the public three-symbol unary machine. Its output decoder is proved only on simulator-reached outputs.

The three-symbol tape codec represents each simulator symbol by a 13-cell block, maps the implicit blank to 13 blanks, and proves quotient-safe initial, read, move and write tape correspondences. A later module constructs the finite-control block reader/interpreter. The public unary input and output conventions remain open; a later module extracts a three-symbol `Machine.Program` for block-encoded tapes.

The three-symbol control machine has finite labels and finite storage. Its proof covers a read phase, a move/write or halt phase, both tape-motion directions, and whole-run evaluation on block-encoded input with block-encoded output. The quotient-safe output encoding is injective. Numerical correspondence is stated via an encoded source-output witness; it is not the public unary decoder; a later module supplies a standalone block decoder. A later module provides finite TM1-to-TM0 table extraction; verified unary pre/postprocessing remains open.

The generic finite TM1 extraction enumerates labels, stores, and substatements, numbers the resulting TM0 states, and proves exact partial evaluation. Its block-simulator instance produces a three-symbol `Machine.Program` with the same block-encoded evaluation. The enumeration includes all 3^13 stores; full materialization and practical resource bounds have not been established. A separate tiny example checks all nine entries of its compiled table and an execution. A later module supplies a standalone block-output decoder; a unary transducer and arbitrary-syntax translators remain open.

An executable finite-list block decoder now round-trips arbitrary encoded source-symbol lists. Its proof assumes a finite list of complete blocks; a later module extends it to blank-extended tapes; public unary postprocessing remains open.

The quotient-safe block decoder is an executable left inverse of the block tape encoding. Composed with the source numeric observer, it establishes numerical and no-result correspondence for compiled finite tables on encoded inputs without an existential source-output witness. Its handling of malformed blocks and noncanonical source encodings is permissive, and the theorem uses reached compiled outputs. This observer is not a finite-machine unary converter.

The unary preprocessing work now includes an explicit table and general run proof for inserting a fixed 13-cell block before a nonempty unary run. It composes a 13-stage unary shift, rewind, and fixed block writer via a finite-table sequencer. This preserves the entire unary run; a later module consumes and replaces each unary symbol; connecting to the simulator, converting its output, and exact partial-result semantics remain open. The complete 318-entry insertion table was exercised on a small example; this is distinct from the much larger extracted block-simulator table.

The unary block loop now consumes a nonempty unary run and emits one fixed 13-cell block per cell, with a proved final tape and halt. It branches on whether another unary cell follows, uses the general consume-and-insert operation for nonfinal cells, and invokes the fixed writer for the last cell. A later module supplies a fixed prefix and rewind; the arithmetic interpretation and integration into the simulated machine remain unproved.

The generic unary preprocessor now inserts a fixed nonblank prefix, replaces all unary cells by a fixed nonblank block, and rewinds to the first output cell, with a full finite-run and halt proof. It does not yet instantiate the blocks as the TM2 simulator input or connect to the simulator; neither unary output conversion nor arbitrary-syntax translators are supplied. The sequence theorem proves forward terminating-run composition and is not an exact divergence or no-result theorem.

The input preprocessor is now instantiated with the actual encoded bottom marker and bit-one symbols. Its terminal tape is the simulator input for `2^(n+1)-1`, not `n`, where public unary input represents `n`. Recovering `n` inside the compiled program, connecting the machines with exact undefinedness, and converting numerical output back to unary remain open.

A constructive list-code recovery program searches powers of two and returns `n` on the preprocessor's `2^(n+1)-1` input. The program composes with every numeric recursive code. The finite-table sequencer now reflects terminal runs as well as preserving them, yielding exact observation and no-observation equivalences after a terminating first stage. These results give a single finite table with public unary input whose host-level block-output observations match the lambda compiler exactly. Public unary output, effective arbitrary-syntax translations, full independent review, and end-to-end validation remain open.

The output wrapper converts every defined result to an all-ones binary number and proves strict preservation of the original partial result. Its simulator main track is exactly the bottom marker followed by one bit per required unary output cell. This is a source-level output layout, not an on-machine unary conversion. Other tracks can remain nonblank and must be cleared so that the public decoder does not accept a malformed halt.

The all-ones output source wrapper is now connected to the unary-input finite table. Its reached block tape has the proved main-track shape and the table terminates exactly when the lambda numerical observation is defined. The theorem still requires an on-machine converter that extracts the one-bits and clears all remaining track data; no public unary-output theorem follows from the shape alone.

A checked finite-table operation now clears one encoded output block and advances by exactly 13 cells, with a quotient-tape correspondence. A complete output postprocessor still needs a finite loop, main-track decoding, unary emission, removal of all other tracks, and a proof of the public numerical and no-numerical-result behavior.

For reached output tapes, all simulator tracks are contiguous from the bottom: beyond it, the first fully blank source block implies every later source block is blank, and some such block exists. This proves that an eventual cleanup loop may stop on a fully blank block without overlooking later auxiliary data. The cleanup loop itself and unary emission remain open.

A finite cleanup scan now clears all remaining encoded blocks after output bits have been read, checks the entire 13-cell block before stopping, and preserves arbitrary left-side scratch data. Its 267-entry table is extracted from finite-control TM1 and has a run proof for arbitrary left tape, with a blank final suffix under the reached-output gaplessness invariant. Reading the needed bits before cleanup, emitting unary, and composing the stages remain open.

The TM1 main-track reader loads the three code cells and returns the decoded main value while restoring the original tape and head position. Its correctness covers blank cells and arbitrary other source tracks. It is not yet composed with unary emission or the finite cleanup table.

The main-track reader has an explicit start label and finite TM0 extraction. The numbered machine reaches a state retaining the read triple, and decoding that triple recovers the source main track while the tape remains unchanged. The total table is defined but not materialized in the size evaluation. Unary emission and sequencing remain open.

A six-state `outputAppend` component adds one cell to a unary scratch run across a marker-delimited blank gap and returns to the waypoint with its right-hand data intact. Its invariant requires the specified blank gap and marker layout; these conditions and the final public head/right-output layout must be established by the remaining composition.

The finite `outputFinish` machine erases the scratch boundary marker, finds the left end of a nonempty unary run, and proves that its terminal head and right side decode correctly when its initial right tail contains only blanks. Its input layout must still be established by the integrated reader/append/cleanup machine.

The finishing theorem also permits any all-blank finite extension beyond the unary scratch on the left and any all-blank right tail. This handles extra represented blanks at both far ends under its stated marker layout; the quotient-to-concrete-layout bridge is still open.

The append operation also permits an arbitrary finite blank extension beyond the scratch unary run on the left; it writes into the first such blank and preserves the rest. The right side remains arbitrary and unchanged. The blank-quotient-to-concrete-layout and full stage composition remain open.

The cleanup and finish stages are now actually sequenced: under the output-track gaplessness invariant and an existing marker-separated unary scratch run, the finite composite halts and the public head/right decoder returns its value. The proof bridges arbitrary representatives of the blank quotient. The input-reading and repeated-append stages have not yet been integrated to establish that scratch run.

The finite `markAppendNext` composite replaces one already-read 13-symbol block, appends a unary cell on scratch, clears the waypoint, and advances to the next block, preserving its encoded suffix and incrementing the blank gap by 13. It does not inspect whether the source main track is a bit-one; a reader-driven branch and whole-run loop remain necessary.

The reader now reaches a terminal concrete finite-table configuration whose store decodes the main-track value. The `readThenAppend` composite actually runs it before marking, appending and advancing. This is an unconditional one-block branch; it is not yet a value-dependent loop or a complete converter. Previous numbered-reader theorem statements are retained.

A separate nine-state scratch append machine requires only one blank beyond the unary run, tolerates arbitrary older data farther left, and clears the next cell when appending. The finish proof likewise tolerates arbitrary data beyond that reserved blank. Initializing this invariant and integrating these components with quotient-level block reading, iteration and cleanup remain open.

The new finite reader-controlled loop has verified one-pass cases: a read bit-one chooses the safe append/advance body, while a read absent main-track value chooses the whole-block cleanup and finishing stage. The scratch permits arbitrary older left data beyond one reserved blank. Iterating those cases, establishing the initial scratch/header layout and deriving the final equivalence are not yet proved.

A finite `unaryOutputConverter` now maps the reached all-ones encoded simulator output to the exact public unary observation under the joint output-track and main-track invariants, with arbitrary initial left tape. It initializes scratch, removes the header, iterates value-dependent reader control, and uses whole-block cleanup. Its composition with the compiled unary-input machine and full defined/undefined correspondence remain open.

The numeric-code compiler now composes unary input, the finite simulator, and the proved unary output converter. For every code and input, its public `Yields` relation is equivalent to numerical membership for the corresponding closed compiled lambda term, and no numerical result is equivalent to that partial value being none. The proof reflects first-stage termination and handles public observations exactly. Arbitrary lambda-to-code and finite-machine-to-code executable translators, as distinct from extensional existence, remain open. The code-indexed machine can be very large; no practical table-size bound is claimed.

The exact extensional class theorem now connects closed lambda numerical computability with all finite three-symbol unary machines in the public model, and gives term-to-machine and machine-to-closed-term existence with matching numerical results. It uses existential partial-recursive code selection in the arbitrary-syntax directions and does not discharge the requested executable translators.

`ExecutableTermCoding` gives a computable term decoder compatible with the existing coding. `UniformLambdaEval` and `UniformMachineSyntax` prove uniform evaluator existence and provide assemblers with correctness conditional on a supplied evaluator code. The concrete closed evaluator codes and hence unconditional executable arbitrary-syntax translators remain open. `UnaryCodegenAudit` checks compilation of an unselected machine-construction branch; it does not evaluate a full generated table or establish practical bounds.

`EffectiveCode` carries recursive-program syntax together with a proof of its exact semantics. `ProofReifier` is an experimental elaborator that constructs such witnesses from supported primitive-recursive and partial-recursive proof forms; the kernel checks the generated witness. It synthesizes the included addition and nowhere-defined examples, but it has not synthesized either uniform evaluator. The general translators therefore remain open.

The reifier now checks the resulting witness type against the function in its input proof, even when no expected result type is supplied, and rejects unresolved function metavariables. The nowhere-defined example has an explicit type and a proof for every input. `FastPpred` supplies a direct, verified code for partial predecessor and is used as a reifier shortcut. The uniform evaluator codes and complete translators remain open.

The encoded-tape modules construct explicit recursive programs for numerical arithmetic, Mathlib-encoded list construction and projections, tape projections, and the public machine's left, right, and write actions. `performCode_eval` proves the action program correct on every valid encoded action and tape, including empty tape sides. Its internal selector requires both branches to produce values; this condition is proved for the finite tape operations. No behavior on malformed codes is claimed. Table lookup, whole-machine execution, concrete uniform evaluators and unconditional arbitrary-syntax translators remain open.

`EncodedMachineStep` constructs a concrete recursive program for one finite-machine transition. It combines encoded table lookup, including missing and explicit halt entries, with the verified tape-action program. Its theorem covers every public finite program and valid encoded configuration after the established state-erasure translation. Whole-run execution, unary observation, concrete uniform evaluators, and unconditional arbitrary-syntax translators remain open; the one-step theorem makes no malformed-encoding claim.

`EncodedMachineRun` constructs an explicit recursive program that executes exactly a supplied finite number of transitions and returns the encoding of an optional configuration. It preserves early halts as an encoded `none` and is proved correct for every valid public finite machine and configuration. This is a defined bounded result, not unbounded numerical observation or a divergence claim. Output decoding, the complete universal evaluators and unconditional arbitrary-syntax translators remain open.

`EncodedMachineEvaluator` supplies a concrete universal finite-machine evaluator and an explicit `machineToLambda` compiler for every public finite program. Its correctness theorem proves closedness and exact numerical-result correspondence, including absence of a numerical result for malformed halting output or nontermination. The direct finite-table encoder is proved equal to the existing encoding. The evaluator and compiler definitions have no axiom dependencies in the Lean audit; their correctness proofs use standard axioms. The reverse arbitrary-lambda-to-machine compiler, independent review, fresh validation, and complete distribution/license audit remain open.

The direct lambda-code modules add a separate injective numerical term encoding with strictly smaller proper subterms, explicit Church-numeral application and recognition, and an explicit course-of-values/history program. The recognizer is proved correct for both Church numerals and all other terms. These definitions have no axiom dependencies in the Lean audit. This is infrastructure for the reverse translation; beta-step evaluation, the complete lambda evaluator, and the arbitrary lambda-to-machine compiler remain open. No practical runtime bound is claimed.

The direct substitution modules construct explicit recursive programs for `liftFrom`, `liftBy`, and capture-avoiding `substAt`, and prove exact correctness for every term, replacement, and depth. The program definitions have no axiom dependencies. `DirectBetaPath` defines a finite-path beta operation and proves that its successful results are exactly the full beta steps, including abstraction bodies and both application branches. `DirectBetaCode` compiles this operation to an explicit total recursive program, with exact encoded optional-result correctness. Its executable definitions have no axiom dependencies. Full reachability search and the lambda-to-machine translator remain open.

`DirectBetaCertificates` proves that finite sequences of path choices characterize full-beta reachability. `DirectBetaTraceCode` gives a total explicit recursive program that executes each well-formed encoded certificate and proves its exact optional-result semantics. Soundness for arbitrary numeric certificate inputs, unbounded numeral search, and the lambda-to-machine translator remain open.

`DirectCertificateValidation` and `DirectCertificateValidatorCode` validate arbitrary numeric encodings of finite path certificates. `DirectSafeCertificate` rejects invalid certificates, and `DirectCertificateObservation` proves that a numeral is observable by some certificate exactly when it is reachable by full beta reduction. `DirectLambdaEvaluator` builds an explicit recursive evaluator for the exact partial numerical semantics, and `DirectLambdaToMachine` combines it with the finite unary-machine compiler. `explicitTranslations_correct` states both translation directions for arbitrary source syntax and every public finite three-symbol table; absence of any numerical result follows pointwise. The direct evaluator program has no axiom dependencies. Lean reports standard axioms including `Classical.choice` on the machine translation definition, so its computational dependency closure still needs review. A code-generation probe compiles an unselected translation branch but does not materialize its large table or provide a practical size bound.
