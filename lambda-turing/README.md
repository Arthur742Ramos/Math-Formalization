# Lambda calculus and Turing computability

An independent source-only Lake build and fresh Lean-kernel replay passed for the full package at `dfd74bf018d74cf472fed0352f054ba017441948`. Later configuration and documentation changes require source-bound checks and review. The protected comparator, external kernels, renderer and runtime computational-closure audit remain open; this is not yet a submission-ready release.

The standalone Challenge states the concrete models and uses eight deliberate placeholders solely for the two translators and their comparison theorems. The Solution does not import the Challenge; its proof closure must be checked independently for placeholders. Exact Challenge/Solution definition correspondence and the protected comparator remain unchecked. See `MATERIAL-DEFINITIONS.md` for the outstanding statement and provenance work.

The machine compiler is not claimed to be practical: the source enumerates at least `3^13 = 1,594,323` block stores, and the extracted block table has at least 4,782,972 slots. These are source-level lower bounds, not measurements of a fully materialized table, running time, or memory use.

Work in progress by Arthur Freitas Ramos, David Barros Hulak, and Ruy José Guerra Barretto de Queiroz. The package proves the extensional equivalence for its public finite three-symbol unary-machine model and defines explicit translations in both directions, with exact numerical and no-numerical-result correspondence. The completed translation chain has received targeted internal review; the computational-dependency closure, protected comparison and complete release review remain open, so the package is not ready for submission. The repository's Apache 2.0 license and retained third-party notices apply; see `THIRD_PARTY_NOTICES.md`.

The intended result concerns closed untyped de Bruijn lambda terms with full beta reduction and Church numeral observations, and unary partial numerical functions computed by a standard finite Turing machine. A missing numerical result must mean absence of a numerical observation, including a nonnumerical normal form or nonstandard machine halt; it must not silently be equated with divergence. Both translations must be explicit and verified, including defined and undefined cases.

The module descriptions below record the scope of individual increments in development order. Statements that a feature was open in an increment describe that local milestone; later modules establish the present extensional theorem. The remaining package-wide obligations are stated above and in the final entries.

This is related to the Isabelle development at reviewed commit `6fed1b6e77514ec161a8fd4718fde1587f2cf624`, including its exact numerical-result semantics and general recursive compiler. Earlier machine-checked work includes Michael Norrish, “Mechanised computability theory” (2011), https://doi.org/10.1007/978-3-642-22863-6_22, HOL4 lambda calculus and recursive functions, and Yannick Forster et al., “A Mechanised Proof of the Time Invariance Thesis for the Weak Call-By-Value λ-Calculus” (ITP 2021), https://doi.org/10.4230/LIPIcs.ITP.2021.19, Coq weak call-by-value lambda calculus and Turing machines. We make no claim of the first formalization of computability equivalence.

`LambdaTuring.Machine` defines explicit finite transition tables over a three-symbol tape, a concrete unary input and partial output decoder, and finite-run semantics. It proves uniqueness of a numerical output, invariance under trailing blank cells, and exhibits a machine that halts with a nonnumerical output. For the three-symbol alphabet and `Fin (states + 1)` state set, `LambdaTuring.MathlibBridge` translates between explicit tables and Mathlib TM0, proves the left and right moves, initial configurations, steps, complete partial evaluations and exact numerical-result correspondence, and proves that decoding is well defined on Mathlib blank-extended tapes. Simulation of arbitrary finite alphabets and correspondence with the Isabelle machine semantics remain open. `LambdaTuring.Observation` gives a full-beta example that reaches a nonnumerical normal form and reaches no Church numeral. The general confluence and uniqueness results are supplied separately by `LambdaTuring.SemanticBridge`.
`LambdaTuring.FiniteTable` enumerates any finite-state transition function over the three symbols into a table and proves recovery of each entry. Mathlib TM0 includes other alphabets and potentially infinite state spaces, which this result does not yet cover.


`LambdaTuring.SemanticBridge` proves a two-way correspondence of terms, shifting, substitution and full beta steps with an attributed port of [CSLib pull request 475](https://github.com/leanprover/cslib/pull/475) at commit `cd9bd6ba0537764eb422532400e99b2c90f34256`. The added bridge and source-fidelity mapping have not yet received independent review.

`CPS` formalizes a strict continuation invariant: defined computations pass their result to any continuation; undefined computations have no beta-reachable normal form for any continuation. It proves that wrapping such a program with the identity continuation exactly represents its partial numerical function, and provides a primitive-recursive CPS compiler for canonical constant and identity codes. The invariant and normalization argument follow the related Isabelle `Lambda_CPS` theory and the continuation method credited there to Norrish (2011). Later modules handle primitive recursion and minimization; independent review is required.

A `none` compiler result means unsupported syntax. This increment requires independent review.

Later modules establish the corresponding scratch invariant using a reader/append loop.

`OutputMarkBlock` and `OutputAppendBridge` construct and compose a finite one-block operation: after the block has already been read, it replaces the block with a waypoint, appends one unary cell to scratch, clears the waypoint, and advances to the next encoded source cell. The theorem preserves the unprocessed tail and is valid for arbitrary blank-quotient tape representatives. Later modules add value-dependent control, the full loop and the initial scratch layout.

`ReaderFiniteControl` lifts the numbered reader run and its terminal stored triple to the concrete finite-table semantics. `OutputReadAppend` sequences that reader with the one-block append/advance machine, so the source value is obtained before the block is erased. This sequence appends unconditionally; later modules add value-dependent branching, repetition and initial scratch setup.

`OutputSafeAppend` addresses potentially arbitrary older data on the simulator’s left tape. Given one reserved blank adjacent to unary scratch, its finite append machine writes one cell and clears the next cell, re-establishing that blank while preserving the right side; the finishing theorem also accepts arbitrary data beyond that reserved blank. Later modules integrate this stronger invariant and machine with the reader-driven converter.

`OutputSafeBridge`, `OutputDispatch` and `OutputValueLoop` connect arbitrary-left scratch through the tape quotient to finite reader-driven control. A verified bit-one pass reads before overwriting, appends one cell, and returns to the reader; a verified missing-main-track branch invokes whole-block cleanup and public finishing. Later modules prove repetition across the output, initialization and the code-indexed end-to-end theorem.

`OutputRepeat` and `OutputInitialize` construct a finite encoded-output-to-unary converter. Under the reached simulator output invariants, it initializes scratch despite arbitrary left-tape data, removes the header, branches on each read value, repeats over all one bits, clears all remaining tracks, and halts with the exact public numerical result. A later module composes it with the compiled simulator and proves undefinedness reflection; effective arbitrary-syntax translators remain open.

`OutputEndToEnd` constructs a finite unary-input/unary-output machine for every numeric partial-recursive code and proves that its numerical observations exactly match the corresponding compiled closed lambda term, including exact absence of a numerical result. This is code-indexed; effective translations starting from arbitrary lambda and finite-machine syntax, full independent review, and fresh validation remain open.

`ExtensionalMachine` proves that closed lambda numerical computability and the public finite three-symbol unary-machine model have exactly the same partial numerical functions, including absence of a numerical result. Its arbitrary-syntax existence directions use Mathlib’s existential partial-recursive code theorem; they are not executable syntax translators. Those translators, independent review and final fresh validation remain open.

`ExecutableTermCoding` gives a computable term decoder compatible with the existing coding. `UniformLambdaEval` and `UniformMachineSyntax` prove uniform evaluator existence and provide assemblers with correctness conditional on a supplied evaluator code. The concrete closed evaluator codes and hence unconditional executable arbitrary-syntax translators remain open. `UnaryCodegenAudit` checks compilation of an unselected machine-construction branch; it does not evaluate a full generated table or establish practical bounds.

`EffectiveCode` carries recursive-program syntax together with a proof of its exact semantics. `ProofReifier` is an experimental elaborator that constructs such witnesses from supported primitive-recursive and partial-recursive proof forms; the kernel checks the generated witness. It synthesizes the included addition and nowhere-defined examples, but it has not synthesized either uniform evaluator. The general translators therefore remain open.

The reifier now checks the resulting witness type against the function in its input proof, even when no expected result type is supplied, and rejects unresolved function metavariables. The nowhere-defined example has an explicit type and a proof for every input. `FastPpred` supplies a direct, verified code for partial predecessor and is used as a reifier shortcut. The uniform evaluator codes and complete translators remain open.

The encoded-tape modules construct explicit recursive programs for numerical arithmetic, Mathlib-encoded list construction and projections, tape projections, and the public machine's left, right, and write actions. `performCode_eval` proves the action program correct on every valid encoded action and tape, including empty tape sides. Its internal selector requires both branches to produce values; this condition is proved for the finite tape operations. No behavior on malformed codes is claimed. Table lookup, whole-machine execution, concrete uniform evaluators and unconditional arbitrary-syntax translators remain open.

`EncodedMachineStep` constructs a concrete recursive program for one finite-machine transition. It combines encoded table lookup, including missing and explicit halt entries, with the verified tape-action program. Its theorem covers every public finite program and valid encoded configuration after the established state-erasure translation. Whole-run execution, unary observation, concrete uniform evaluators, and unconditional arbitrary-syntax translators remain open; the one-step theorem makes no malformed-encoding claim.

`EncodedMachineRun` constructs an explicit recursive program that executes exactly a supplied finite number of transitions and returns the encoding of an optional configuration. It preserves early halts as an encoded `none` and is proved correct for every valid public finite machine and configuration. This is a defined bounded result, not unbounded numerical observation or a divergence claim. Output decoding, the complete universal evaluators and unconditional arbitrary-syntax translators remain open.

`EncodedMachineEvaluator` supplies a concrete universal finite-machine evaluator and an explicit `machineToLambda` compiler for every public finite program. Its correctness theorem proves closedness and exact numerical-result correspondence, including absence of a numerical result for malformed halting output or nontermination. The direct finite-table encoder is proved equal to the existing encoding. The evaluator and compiler definitions have no axiom dependencies in the Lean audit; their correctness proofs use standard axioms. The reverse arbitrary-lambda-to-machine compiler, independent review, fresh validation, and complete distribution/license audit remain open.

The direct lambda-code modules add a separate injective numerical term encoding with strictly smaller proper subterms, explicit Church-numeral application and recognition, and an explicit course-of-values/history program. The recognizer is proved correct for both Church numerals and all other terms. These definitions have no axiom dependencies in the Lean audit. This is infrastructure for the reverse translation; beta-step evaluation, the complete lambda evaluator, and the arbitrary lambda-to-machine compiler remain open. No practical runtime bound is claimed.

The direct substitution modules construct explicit recursive programs for `liftFrom`, `liftBy`, and capture-avoiding `substAt`, and prove exact correctness for every term, replacement, and depth. The program definitions have no axiom dependencies. `DirectBetaPath` defines a finite-path beta operation and proves that its successful results are exactly the full beta steps, including abstraction bodies and both application branches. `DirectBetaCode` compiles this operation to an explicit total recursive program, with exact encoded optional-result correctness. Its executable definitions have no axiom dependencies. Full reachability search and the lambda-to-machine translator remain open.

`DirectBetaCertificates` proves that finite sequences of path choices characterize full-beta reachability. `DirectBetaTraceCode` gives a total explicit recursive program that executes each well-formed encoded certificate and proves its exact optional-result semantics. Soundness for arbitrary numeric certificate inputs, unbounded numeral search, and the lambda-to-machine translator remain open.

`DirectCertificateValidation` and `DirectCertificateValidatorCode` validate arbitrary numeric encodings of finite path certificates. `DirectSafeCertificate` rejects invalid certificates, and `DirectCertificateObservation` proves that a numeral is observable by some certificate exactly when it is reachable by full beta reduction. `DirectLambdaEvaluator` builds an explicit recursive evaluator for the exact partial numerical semantics, and `DirectLambdaToMachine` combines it with the finite unary-machine compiler. `explicitTranslations_correct` states both translation directions for arbitrary source syntax and every public finite three-symbol table; absence of any numerical result follows pointwise. The direct evaluator program has no axiom dependencies. Lean reports standard axioms including `Classical.choice` on the machine translation definition, so its computational dependency closure still needs review. A code-generation probe compiles an unselected translation branch but does not materialize its large table or provide a practical size bound.
