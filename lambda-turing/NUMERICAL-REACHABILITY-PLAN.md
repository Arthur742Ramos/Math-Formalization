# Campaign: numerical reachability in full beta reduction

## First target

For `Term` under the existing full-beta relation, define `NumeralReach t := ∃ m, Reaches t (church m)`. Prove it is recursively enumerable and many-one complete for recursively enumerable predicates in Mathlib's `Primcodable`/`Computable` sense. The hardness reduction is explicit: for `(c, x) : Nat.Partrec.Code × Nat`, construct `Term.app (compileLambdaTotal (Code.comp c (Code.const x))) (church 0)`, prove this syntax is closed and the map is primitive recursive, and prove its numeral reachability iff `(Code.eval c x).Dom`. Thus hardness holds even with the input restricted to closed output terms; formulate a closed-input decision impossibility without implicitly assuming an unproved effective coding of the closed-term subtype. The draft additionally proves that scope testing is primitive recursive and that `Scoped 0 t ∧ NumeralReach t`, interpreted as a language over all encoded terms, is r.e.-complete. It does not introduce a separately encoded closed-term subtype.

The locally checked `NumeralReduction.lean` proves closedness, primitive recursiveness and exact correctness of that reduction, a uniform partial-recursive observer, `REPred NumeralReach`, many-one hardness for every r.e. predicate with closed output, undecidability even for closed-input deciders, and non-r.e. complement. It uses `primrec_compileLambdaTotal`, an existing mathematical proof of compiler effectivity, not merely native compiler/codegen evidence. These are direct local checks using partly cached dependencies; an independent review and clean package build remain open. The strengthened draft also proves r.e.-completeness and non-r.e. complement for the closed-term language over all encoded terms. The proof is about full beta reachability of numerals, not weak normalization or divergence.

## Library reuse and remaining proof chain

* Pinned Mathlib `Mathlib.Computability.Reduce` defines `ManyOneReducible` and closure/transfer theorems; `RE` provides `REPred`, `Partrec.dom_re` and complement/decidability results; `Halting` proves fixed-input Code halting r.e., undecidable, and its complement not r.e. `PartrecCode` provides universal partial evaluation, `exists_code`, `Code.primrec_const`, `Code.primrec₂_comp`, curry/s-m-n and fixed-point infrastructure. These are existing results, not new claims.
* The local `CPSTotalCompiler` already proves `primrec_compileLambdaTotal` and exact `compileLambdaTotal_sound`. `FoldCode` gives the effective coding of terms and primitive-recursive constructors; `Basic` supplies `church_closed` and the reduction relation.
* The checked upper-bound foundation uses `uniformNumericalValue_partrec` in `UniformLambdaEval`, `primrec_liftFrom`, `primrec_abs`, `substAt_liftFrom`, and `reaches_numeral_join`. The computable wrapper `abs (liftFrom 0 t)` applied to Church 0 beta-reduces to arbitrary `t`; confluence plus numeral normality makes its numerical observation equivalent to `NumeralReach t`. Its uniform partial result gives the exact domain; the checked theorem applies `Partrec.dom_re` to obtain `REPred NumeralReach`. Mathlib RE, Reduce and Halting were built into a separate local overlay from pinned source, reusing other cached dependencies.
* The checked many-one hardness proof takes an arbitrary r.e. predicate on a `Primcodable` type, uses its partial-recursive witness and Mathlib's code-representation theorem for the encoded partial computation, and composes the resulting fixed code with the computable input encoding and the explicit reduction above. The existence of a fixed code is sufficient for an existential many-one theorem; it is not claimed to be a computable extraction from a proof of r.e.-ness. The proof explicitly establishes the encoding and partial-output domain bridge.
* The checked corollaries apply Mathlib's fixed-input halting undecidability to rule out a computable decider on all terms and a computable Boolean procedure correct on closed terms, and use Mathlib's r.e./co-r.e. characterization to show the complement over all terms is not r.e. They do not infer divergence from absence of a numerical result.

## Follow-on work

1. Many-one equivalence for the actual finite three-symbol unary-machine acceptance model, proving effective finite-table coding and exact malformed-halt/no-result semantics; do not treat merely executable translator syntax as a `Computable` theorem.
2. Transport Mathlib Rice results to extensional properties of closed lambda programs after proving the necessary effective encoding/compiler map and precise nontriviality assumptions.
3. Investigate totality, arithmetical hierarchy and Rice–Shapiro only after these foundations; any normalization or divergence theorem requires a separate semantic bridge.

This is a substantive formalization of a classical result, not a claim of new mathematics or the first mechanization. Independent source and scope review and exact-source builds are required before publication. The initial direct Lean check uses cached dependencies and is not a clean package build.
